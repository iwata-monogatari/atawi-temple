## 1. 目的

現在の寺院個別ページは「基礎情報・調査中」段階のものが多く、出典5件前後・本文2〜3セクションの構成にとどまっている。本改修では、Claudeのリサーチ機能（Research）を用いて全寺院を1件ずつ深掘り調査し、以下を達成する。

1. 全118ページの本文・出典・「これから調べること」を、リサーチ結果に基づき全面書き換えする
2. 出典の質と量を引き上げ、「公開資料と現地確認をもとに整理」というサイトの信頼性主張を実体化する
3. ページ充実度（品質等級）を全件で再判定し、/status/ の調査状況と同期する
4. 三層コンテンツアーキテクチャ（集客層・橋渡し層・転換層)の「集客層」としての検索受け皿を強化する
5. **各ページの本文ボリュームを現行比200%以上に引き上げる**（水増しではなく、リサーチ深度と新設セクションによる構造的増量。基準は第5章）

## 2. 大原則(変更禁止事項)

- **寺院コンテンツ層に不動産語彙を一切使用しない**。売却・査定・空き家・実家じまい等の語は個別ページ本文・見出し・メタに入れない
- **CTAはページあたり最大2カ所**。導線は既存の real_estate_funnel:on/off フラグとテンプレートで管理し、本文には手書きしない
- **個別ページの手編集禁止**。リサーチ結果は必ず寺院データ(facts/JSON)に落とし、生成パイプラインで再生成する
- **デプロイはGitHub push → Cloudflare Pages のみ**(Direct Upload禁止)
- **学説・伝承が対立する場合は断定せず併記**(磐田物語と同一方針)
- **未確認情報は「これから調べること」に公開**し、空欄や推測で埋めない(現行方針を維持・強化)

## 3. リサーチ機能の運用ルール

### 3-1. 実行単位

- **1寺院 = 1リサーチ**を原則とする(118回)
- 例外:登録情報が極端に少ない廃寺・寺院跡は、同一地区でまとめて1リサーチ可(最大5件/回)

### 3-2. リサーチ項目

1. 山号・院号・正式名称の表記ゆれと典拠
2. 創建年代・開山・開基の伝承と、それを記す資料(寺伝/市誌/県資料)
3. 沿革上の主要事件(兵火・移転・再建・合併・廃仏毀釈期の状況)
4. 本尊・霊場札所・年中行事
5. 文化財(国・県・市指定/登録)と指定台帳上の名称・区分
6. 境内の見どころ(建造物・庭園・古木・石造物)
7. 地域史との関わり(東海道・遠江国府・天竜川・掛塚湊など地区文脈)
8. 現況(宗教法人としての現存/廃寺、公式サイト・SNSの有無)

### 3-3. リサーチ結果の採用基準(3段階)

| 区分 | 基準 | ページでの扱い |
|---|---|---|
| A:確定 | 行政資料・指定台帳・宗教法人名簿・寺院公式で確認 | 本文に記載+出典欄に必ず対応 |
| B:伝承・二次 | 寺伝、市誌の伝承記述、信頼できる二次情報 | 「〜と伝わる」「〜とされる」で記載+出典明示 |
| C:未確認 | 出典が取れない・矛盾がある | 本文に書かず「これから調べること」へ |

- 出典のない断定文を1文でも含むページは公開不可(verify思想の踏襲)
- リンク切れURLは出典に採用しない(リサーチ後に200応答を確認)

## 4. 新ページ構成(共通テンプレート)

01 この寺院について / 02 歴史と背景 / 03 文化財・見どころ / 04 宗派と本尊を知る(新設・共通モジュール+個別化文100字以上) / 05 地域とのつながり(新設・磐田物語クロスリンク枠) / 06 年中行事・参拝の手引き(新設・廃寺は出力せず跡地現況を05へ) / 07 よくある質問FAQ(新設・FAQ構造化データ出力) / 08 写真で見る境内 / 09 出典・参考資料(区分ラベル+確認内容注記必須)

- ボリューム水増し禁止(増量はリサーチ事実・モジュール個別化・FAQ要約のみ)
- 文体はですます調、算用数字+元号(西暦)併記、正式表記はページ内統一

## 5. 充実度(品質等級)

| 等級 | 表示名 | 本文字数下限 | 出典 | その他基準 |
|---|---|---|---|---|
| T1 | 充実 | 6,000字以上 | 12件以上 | 全セクション記載・現地写真あり・FAQ6問以上 |
| T2 | 標準 | 4,500字以上 | 8件以上 | 01〜05+07記載・写真は準備中でも可 |
| T3 | 基礎情報 | 2,500字以上 | 5件以上 | 廃寺・小庵。05の地区文脈と跡地現況で構成 |

- いずれの等級でも改修前の同ページ本文の200%以上を必須条件とする(`data/refurb-baseline.json` に機械計測値を記録)
- 目標配分:T1=30件以上、T2=60件以上、T3=残り

## 6. データと生成パイプライン

- リサーチ結果は寺院ごとの facts ファイル `data/temples/<slug>.json` に集約
- 機械検証(公開ゲート)は `scripts/verify-refurb.mjs`:
  1. 出典URLの生存確認 2. 出典件数の等級基準 3. 禁止語(不動産語彙等) 4. 内部リンク
  5. canonical・title・meta 6. 字数(改修前200%かつ等級下限) 7. モジュール個別化文(100字以上)

## 7. 作業フロー

リサーチ→A/B/C採用判定→facts JSON作成→ページ再生成→機械検証→push→本番確認→/updates/反映

### Git安全ルール(毎回厳守)

git fetch → git status → git pull --ff-only → 変更ファイルのみpath指定でgit add(git add -A 禁止) → commit → push(--force 禁止) → デプロイ後に過去ページの消失がないことを確認
